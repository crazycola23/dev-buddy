# 开发搭子 · Dev Buddy

一个面向跨层开发任务的 Codex Agent Skill。

它让 AI 交付最小、完整、可验证的垂直切片，同时保留你理解和维护代码所需的关键链路。重点不是让 AI 扮演所有开发角色，而是给跨层任务一套稳定、克制、可追踪的决策程序。

## 核心目标

```text
完成一个可验证的垂直切片
  → 保持项目已有约定
  → 讲清受影响的关键链路
```

## 两条执行路径

- **局部快速路径**：故障和范围明确时，只检查相关代码与调用方，做最小修复并运行针对性验证。
- **跨层垂直切片**：任务跨越前端、API、后端、数据层或外部集成时，只追踪受影响链路并完成两端契约。

一旦调用链、契约和项目约定已经有足够证据，skill 会停止扩大阅读范围，不扫描无关模块。

## 决策规则

- 现有代码拥有业务约定、错误格式、状态与数据模式。
- 框架拥有生命周期、校验、序列化和事务等基础机制。
- 新代码只拥有当前需求要求的行为。
- 新抽象必须有真实消费者、稳定边界、框架要求，或隔离了有测试覆盖的高风险问题。
- 简单不等于脆弱；按风险保留权限、事务、并发、错误处理和可测试性。

## 默认讲解

每次交付默认只讲清：

1. 这次改了什么；
2. 请求或数据怎么走；
3. 最不显然的一个设计决策。

只有你明确要求学习或深入分析时，才扩展 What / Why / When / Alternatives、失败预测和理解检查。

## 适用范围

适合：

- 跨前端、后端、数据库或外部集成的实现；
- 希望 AI 写出完整代码，同时自己掌握架构链路；
- 显式使用“开发搭子”处理局部问题，此时自动走快速路径。

不应自动触发：

- 琐碎的局部编辑；
- 只改格式；
- 没有架构影响的依赖升级；
- 不包含实现的纯解释请求。

## 使用

```text
$dev-buddy 帮我完成订单取消功能，包含前端状态、Spring Boot API 和数据库更新，并讲清关键链路。
```

需要深入学习时直接说明主题：

```text
$dev-buddy 完成这个功能，并重点带我理解 Spring 事务边界和失败回滚。
```
